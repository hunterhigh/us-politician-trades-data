# 来源共用实现

五个来源候选适配器与年报覆盖共用 `candidates.py` 的 `candidate_source` 执行器。适配器在来源规则之间给出 `CandidatePlan`，由唯一的 `assemble` 实现处理复制／原地更新、数组替换与追加、排序、元数据、来源健康、已选年报重建和规范化检查。输入不满足来源门禁时，适配器按原规则拒绝，不生成空候选替代失败。

- `records.py`：内容寻址归档、不可变写入、稳定元数据核对、JSON 字节编码及对象读取。
- `members.py`：名册 GET 重试、XML 外层安全检查及名称字符分解；读取响应共用 `source_transport.read_response`。
- `annual.py`：按适配器给出的排名选择版本，以及披露行字段映射。House 保留原有完整排名和首个并列项；Senate 保留最新年报年份的全部版本，再执行自身修订规则。

来源模块保留官方 URL／授权、输入格式、字段映射、金额与日期解释、身份绑定、修订与副本关系、隔离原因、审计文本等差异。Senate 授权会话与 OGE／House 的重试及错误策略保持原样。旧模块名和函数签名继续作为调用入口，识别冻结包、fact_policy、builder、发布整合实现和工作流未因本次合并修改。

`CandidatePlan.copy=False` 保持原有原地修改语义；未配置排序的数组保持顺序。归档配置继续区分返回首次归档元数据和返回本次观察元数据、稳定字段集合、原有原子／直接写入方式及错误类型；不统一这些来源语义。
