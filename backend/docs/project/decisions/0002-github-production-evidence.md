# 0002：GitHub 生产环境与公开证据分支

日期：2026-09-18

## 背景

项目已从离线原型进入公开 GitHub 生产运行。只保存规范化快照和检查点无法独立完成来源审计，也无法在官方原件暂时不可用时恢复解析输入。

## 决定

同一公开仓库使用四个分支：`code` 保存实现，`main` 保存规范化快照，`state` 保存运行检查点，`evidence` 按 SHA-256 保存官方索引 ZIP、PTR PDF 和获取元数据。House 工作流先持久化 evidence，再推进 state。每轮只处理有界批次。

生产 workflow 绑定 GitHub `production` environment。仓库写入只使用自动签发的 `GITHUB_TOKEN`；外部供应商凭证仅使用 environment secrets。

## 后果

- 原件、哈希、来源 URL 和获取时间可以按 Git commit 审计和恢复。
- 前端读取 `main` 时不下载 PDF，报告速度不受证据层影响。
- Git 对长期累积二进制文件的空间效率较低，必须监控容量，并在达到边界前迁移证据层。
- 公开仓库中的原件对所有人可见；只归档已确认的官方公开文件，不发布未复核的派生抽取行或任何凭证。

## 复审条件

仓库接近平台容量限制、官方来源使用规则变化、需要删除或限制原件访问，或迁移到对象存储时复审。
