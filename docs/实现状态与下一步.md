## 本轮交付

1. 输入规范校验、显式合成标识、金额范围、日期、外键、重复 ID、字段白名单；真实数据入口关闭。
2. 规范 JSON 字节、SHA-256 内容地址、people/tickers 哈希桶、看板包和 manifest；超出索引或分片预算直接失败，不截断记录。
3. `source_health` 仅在 manifest，健康变化不重写业务分片；业务截止时间改变会改变 snapshot_id，避免相对时间统计缓存过期却不刷新。
4. 独立裸 Git 数据仓库，比较预期旧提交后原子更新 demo 分支与 `published/<SHA>` 标签；失败保留前版、保留旧对象及标签、支持指定版本读取与回退。
5. 本项目本地读取工具重建看板、人物与标的数据；原包处理器和渲染器固定哈希，实际参与验证与页面生成。
6. 只读代理隔离实现，生产 main-only，固定仓库、鉴权、冻结提交、发布标签校验、路径白名单、大小与超时限制；离线模拟上游测试。
7. 离线 CI 配置、合成演示、Git bundle 备份恢复测试与运行说明。
8. 公开 GitHub 首发读取器：先把 `main` 解析成固定 commit，再按该 commit 读取所有文件；支持 dashboard/search/person/ticker，校验内容哈希、demo 边界、依赖和人物引用。
9. 生产工作树物化与手动发布 workflow：生产输入门禁、manifest 最后写、旧内容保留、远端基线复核、`main` 与 `published/<SHA>` 原子推送。
10. House Clerk 单源发现第一段：读取官方年度 ZIP 索引，校验文件布局与行字段，按文件类型生成官方 PDF 地址，并按 SHA-256 不可变归档原始 ZIP 与首次获取元数据。真实 2026 索引验证为 1,653 条，其中 393 条 PTR；空日期保留为未知。所有记录仍标记为 `official_raw_unparsed`。
11. House PTR 受控样本第二段：只有已归档索引确认的 PTR 才能下载；校验重定向、大小、PDF 头尾和内容哈希。5 份真实电子 PTR 共抽取 24 行，覆盖股票、期权、无 ticker、金额换行、跨页行和 amended 申报；每行含页码与坐标证据，并保持 `awaiting_manual_review`。
12. House 人物身份第三段：解析 Clerk 当前议员 XML，跳过官方空缺席位，用选区和姓名共同匹配 BioGuide 稳定 ID。2026-09-02 名册含 439 位在任议员；样本得到 `house:D000032` 建议，但仍需人工接受。
13. 复核晋级门禁：待复核模板要求稳定人物 ID、官方身份链接、来源使用批准、申报时间、具名复核者和全部行决定；缺任一项不能转成 `official_matched`。amended 行必须选择 `replace_prior` 并填写内部旧记录 ID，或选择 `standalone_correction` 并说明无法关联原记录的原因。解析器不直接写生产数组，也不会只凭官方交易编号自动覆盖历史记录。
14. 可恢复增量检查点：按官方索引字段签名维护 pending/failed/archived 状态，逐文档记录尝试结果，失败采用 15 分钟起、最长 24 小时的指数退避；同 ID 字段变化、索引消失、多归档版本、元数据不匹配和证据缺失均进入异常队列。真实 2026 规划得到 393 份 PTR，其中 5 份从归档恢复完成、388 份待处理、0 个索引异常。

## 必须保留的协作边界

- 不修改 `review-input` 的前端基线，不把旧处理器测试当作新版消费端测试。
- 正式代理拒绝合成快照；本地 demo 不接入正式 main。
- `published/<SHA>` 用于证明“技术发布过”，不表示数据授权已成立；不得把 raw 或密钥写进数据发布树。
- 目前按全部输入建 board，没有任意大规模截断/分页；触发大小阈值时应先调整契约和窗口，再恢复发布。
- snapshot_id 包含业务截止时间和展示配置。健康检查时间单独变化不影响它；generated_at 单独变化不创建无意义提交。

## 推荐下一轮顺序

先把 House 增量队列接成有单批上限和失败退避的受控执行器，同时补充扫描件、撤回件等异常黄金样本；再确定真实复核责任人与来源使用批准记录，拿对方新版消费端做互相联调。随后连接用户创建的公开 GitHub 仓库，跑一次无行情的正式候选发布和实际读取；取得运行时长和数据增长后再开启 schedule。Cloudflare 留作以后转私有时启用。
