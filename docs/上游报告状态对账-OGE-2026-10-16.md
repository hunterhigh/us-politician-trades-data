## 5. 复算方法、未闭合项和下一停点

- 固定来源：`evidence` 的 `oge/catalog/05c218...json` 指向 168 个 `oge/catalog/pages/*.json`；逐页读取 `data[*].type`，去 HTML 标签并把修订、申请字样折叠到上述类型族。`oge/catalog/normalized/05c218...json` 是**278-T 子集**，按 `access_method` 分组，并只对非空 `source_document_id` 去重。
- 原件／提取：在固定 `evidence`、`review` 提交分别用 `git ls-tree -r --name-only <commit>` 列出 `oge/reports/*/*.json` 与 `oge/extractions/*/*/*.json`；第三级目录是文档 ID，第四级是 PDF SHA-256。对文档 ID 集合做差；不把 340 个提取文件当作 340 份原件。
- 正式交易：读取固定 `main` 清单引用的 board，筛选 `source_id=oge`；以 `source_url` 主机划分 OGE 直取与白宫公开件，分别对 `filing_id` 去重，并按 `id` 前缀分出白宫年报与 278-T。正式行与候选行分开。当前 review 数只作另一时间的对照。
- 目录范围：16,751 是 2026-10-16 此 API 目录快照的可见 occurrence；278-T 子集还含历史年份及 9 个只在归档历史目录保留的直取 ID，不能从“当前直取已全部归档”推出全历史报告已经覆盖或所有官方文件都可公开直取。需申请项缺唯一文档 ID；白宫逐报告身份／版本；25 个直取无正式行的资格原因，是下一轮只读对账的明确缺口。若资格大文件暂不可读取，维持未知并继续其余来源，不编造跨源总数。

本轮只做读取与集合对账，没有下载官方文件、执行 OCR、修改资格或运行发布。普通对账失败时保留上述固定坐标和差集，再针对缺失键或资格件补查；若发现正式交易确有错误，交由主任务判断是否另开正式事实更正，不在状态统计里暗改。
