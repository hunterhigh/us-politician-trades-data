当前目标是后端数据产品的代码重构。2026-10-23用户纠正了此前再次退回逐份报告、逐条交易恢复的做法：以下16项原件诊断及固定结果是既有证据，不能直接当当前任务队列，也不能按数据条数衡量产品进度。停止继续逐份OCR、补读与样本恢复；数据工作后置，仅在验证已选产品能力时使用必要样本。

## 计划和执行的责任

首轮已完成扫描表格坐标与倾斜行列定位的这一工程缺口。根因是双轴算法复用`_raster_rule_centers`时继承旧模板80–590点的固定纵向窗口，真实表头边界在拟合前已被丢弃。现保留旧调用默认行为，为双轴搜索显式提供页面域，并用七条列线逐段连通证据选择包含三处区域观测的唯一表格分量，排除页眉/页脚横线；最终整段细线、轨迹、倾斜、多解及局部区间检查保持，内部断线保留原失败原因。几何结果再交既有表头角色和字段归属检查。支持边界为现有六列有框表、零原点的已显示MediaBox坐标、线性斜率绝对值不超过.015及原有区域/行距约束；任意无框、弯曲表、过度倾斜和非零原点不在该轮支持范围。

正常CLI现可显式传入`--geometry-mode source_pdf_dual_axis/v1`；配合`--geometry-only`可只检查几何而不触发OCR。双轴路径不再先跑旧固定条带普查，即时OCR与保存重放保留同源MediaBox证明，几何状态和表头角色缺读分别诊断。构造回归覆盖正反横纵倾斜、页面位移/尺寸、裁切/旋转、断线/多解、缺失表头边界及正文词守恒；固定原件仅用于复现：原先遗漏的约70.4点表头上边界现已进入模型，几何CLI重复一致，正常命令与保存重放完全一致，正文词及来源回执不变。该原件的表头文字仍缺读，结果继续为unknown，不补标签或事实。测试见`backend/tests/test_oge_grid_search_domain.py`，本机复现证明见`.local/geometry-domain-check/receipt.json`；代码与完整检查版本见[当前状态](实现状态与下一步.md)。未补数、未发布，连笔日期未涉及。

第二轮已完成House纸表必需复读证据的准备契约。根因是`reread_doubtful_key_cells`仅选质量标记格，而`materialize_paper_observation`要求每条可解释数据行的asset都有来源绑定复读；无警告资产因而被正常入口漏选。选择沿用现有读取器和消费者，新增纯计划`plan_key_field_rereads`与缺项检查`missing_key_field_rereads`：materialization模式列全asset必需读取并合并既有疑难event诊断，先核对坐标、首读裁剪绑定和总预算，再执行；没有列定位的行不生成请求。原doubtful函数默认模式保留，正常桥接和准备CLI显式使用materialization模式。默认每份32格、参数最多64格，超限在渲染/OCR前失败，不截断清单；不扩大识别模型或日期研究。

准备器可接入兼容的同源v2缓存，只读取缺失或首读绑定已变化的请求；已有读数、额外Owner证据及回执保持，完整缓存可原样复用，无需补造计划回执。错源、重复、错计数或过时缓存不复用。保存物化只检查缓存，缺项定位到页/物理行/字段并保留隔离，不启动OCR；真实裁剪像素与读数冲突仍由原消费者检查，准备齐全不代表事实合格。CLI为`python -m unison_snapshot.house_ptr_key_field_reread`，默认准备必需证据，`--plan-only`不渲染或OCR，`--existing-rereads`支持预览缺项或增量准备；识别失败不会写出半份产物或改写输入缓存。测试见`backend/tests/test_house_secondary_preparation.py`及正常桥接/消费者回归：使用构造输入与实际生成PDF验证裁剪哈希消费、重复结果、旧/部分缓存、预算和失败边界，识别器用固定测试输出，不声称新增OCR准确率。第二轮未处理业务数据、未上线，连笔日期继续暂缓。

第三轮修复House空白Owner中的长笔画误判。旧`_blank_paper_owner`会删除边界附近8像素内所有横贯局部窗口的黑线；已构造复现：在正常表框内侧增加一条长线，旧代码仍可给出空白资格。选择用目标格外的独立印刷证据限定删除范围，已接入正常保存物化：`ruled_cell_blank.inspect_ruled_cell_blank`在原有暗像素阈值100下检查整个格；整格无暗像素直接返回blank，有边框暗像素时，使用同页至少两个其他列区间及两个其他物理行区间，求唯一共同直线足迹，再核验目标框线实际连续，最后检查整格剩余像素。目标格内容不参与边框估计，校准格角部和边缘不裁掉；额外长线、角部墨点、断框、多解、参照重叠/缺失均保持unknown。正常Owner资格证据版本为`source_bound_blank_paper_owner/v2`，原件/crop绑定、默认资格门禁及既有正式记录保留逻辑沿用。

该轮支持边界为已有House格位定位可校准的直线薄框，线足迹最多6像素且受格宽/高约束，不支持任意弯曲、倾斜或粗框判空，也不外推到所有声明/空白检查器。独立参照不足时不沿用旧删除法。生成PDF验证实际渲染、裁剪哈希、重复结果，正常物化/候选/builder验证空白可消费、添加笔画不授予Undisclosed；测试为`backend/tests/test_ruled_cell_blank.py`及`test_house_ptr_blank_owner.py`。对E06同哈希历史原图只做一次几何判空检查，页/列定位正常，但边线足迹缺失或多解，仍unknown；证明见`.local/independent-blank-check/historical-frame.json`，不能把构造直框通过说成历史弯曲框已解决。P04总体保持未闭合，旧闭合轮廓试验仍不进入空白资格；没有新边框证据时不重复该识别路线。该轮完整检查为代码`a3c6cc156`通过1861项（`.local/independent-blank-check/backend-verify.log`），未补数、未发布，未恢复连笔日期研究。

第四轮解决House保存物化的多文件中断恢复。P16已提出避免半包及失败恢复的问题；本轮调查确认单文件临时替换并未覆盖整组结果：旧入口先改写legacy引用和extraction、后写observation/header/qualification，若资格写入前失败，新extraction与旧qualification混存，默认选择器因来源绑定不一致停止，无法正常重试。先用实际落盘及故障注入复现，再选择预写整组结果的恢复方法；未改变字段解释、资格或业务规则，也未扩展为全后端事务框架。

`house_paper_commit.py`在替换任何输出前，保存已验证的observation、header、extraction、qualification及可选legacy引用，绑定原件/元数据、身份/复读输入哈希和各目标文件原哈希。逐个原子替换、完整字节核验后才删除pending记录。单份桥接、批量CLI及正常工作流默认选择器均先恢复已准备结果，不重跑解释器或OCR；恢复前一次检查所有目标，原件、输入、内容校验或目标外部改动不匹配则保持pending并停止。同一规范审阅路径的桥接、恢复、候选和报告状态入口使用进程间文件锁，候选和状态拒绝pending状态；锁放在系统临时目录，读取不改动审阅源码目录，进程退出自动释放。支持范围是保留同一审阅目录的进程中断恢复，未声称磁盘掉电事务、运行器磁盘丢失恢复或所有旧脚本写入都已纳入锁。

`backend/tests/test_house_paper_commit.py`覆盖五类输出每次替换前后中断、真实子进程退出及锁释放、并发访问、外部改动拒绝、pending写入前失败；实际执行工作流选择器和批量CLI恢复，再经正常候选/报告状态消费，重复运行字节不变且保留旧失败及legacy来源。使用已有合格/隔离构造结果验证文件交付，不声称新增识别准确率或恢复业务数据。当前代码与完整回归证据见[当前状态](实现状态与下一步.md)。P16的统一重放、发布与生产切换仍未完成。

第五轮解决描述字段分行依据在保存链路中丢失的问题，对应P03及T05的资产词序难点。调查确认Tesseract读取器/OcrPage已有block、paragraph、line标签，但`observe_raster_slots`只保存文字、字框和置信度；下游重新按字框中心猜行，在倾斜及字高变化下反复遇到顺序或方向冲突。构造对照复现了同样两行文字在两种斜率方向结果不一致。选择保留已有分组并附加几何约束，不新增识别模型，不把OCR行标签当已确认事实。严格保存报告会按原输入重算，因此能力使用显式版本，未默认切换旧输入算法。

`oge_ocr_line_order.py`保存完整页级原词记录及哈希、来源/页绑定和槽内原词索引；消费前校验文字、字框、置信度、完整槽内成员及可用的MediaBox词哈希。描述字段按原block/paragraph/line分组，行内仅在原字框不重叠时按x排序；各组须在原坐标或行相对坐标中符合沿用的字高容差，行间须有可分离字框，且两种坐标的行序一致。同一OCR行横跨物理槽、组内无法形成文字带、词框重叠或行序不明时保持unknown，不挑一个值。完整分行资料才启用此路径，旧/部分标记缓存保持原算法，原生PDF对象不被伪造为OCR行。原始字符串和坐标不变；日期、金额仍沿原解释路径。

正常观察CLI通过`--description-line-mode source_ocr_lines/v1`启用，输出携带同版模式与分行来源；字段CLI及现有OGE候选/快照直接消费。White House保存输入可在已有dual-axis模式中设置`description_line_mode: source_ocr_lines/v1`，保存回执记录版本并严格重放；旧输入未设置时保持原路径。`backend/tests/test_oge_ocr_line_order.py`验证正反斜率/字高、行标签跨block及数值顺序、错误合并/拆行、跨槽/重叠、来源引用变化、日期/金额解释不变；生成PDF的正常观察与保存回放、JSON/字段CLI、White House物化重放及OGE候选/builder均已消费。既有正式来源行和ID保持，不凭新排序直接改写或复制。识别器使用固定构造输出，验证的是分行传递和消费能力，不是独立OCR准确率或全部资产跨行能力；P03整体仍未闭合。代码及完整回归证据见[当前状态](实现状态与下一步.md)。

第六轮解决House现代PTR的混合页路由盲区。调查发现`parse_archived_pdf`仅在整份PDF均无文字时启动OCR，工作流安装引擎的条件也相同；生成“有字封面＋无字图像正文”的PDF可复现无交易行且OCR调用为0。选择按页准备与读取，沿用现有现代表字段解释及资格规则。`observe_native_word_pages`与`planned_ocr_pages`供解析和自动准备共用：纯原生、整报OCR保留原路径；对原生首页符合现代PTR标题及文档ID、页面零原点的混合文件，只OCR无文字且有图像/绘图内容的页。无文字且无内容对象的页不据此判空，仍保留覆盖unknown。新增子集OCR保留请求页序并按MediaBox渲染，裁切输入不会另用CropBox原点解释坐标。

混合产物标为`mixed_native_ocr`，保存逐页读取方式、带同版方法标记的原词观察及哈希；每行的`ocr_source_pages`来自实际参与解释的词，而不是包含空区的跨页证据框。资格和候选重放这些保存输入，不再启动OCR；原生行保留原规则、字段和ID，实际使用OCR词的行（含原生起始的OCR续行）继续现有置信度门禁。改动读取方式、来源页、读数或派生资格会被重放检查拒绝；读不出不冒充零交易。支持范围为现代PTR的整页无字内容，不包括已有但不完整的文字层、混合旧式纸表或混合零交易声明的独立覆盖证明，也未扩展混合输入的自动修订前件支持。P05整报覆盖及P06独立完整性问题仍未整体解决。

正常`parse-house-ptr`/`qualify-house-ptr`、候选、状态及builder已消费混合产物；`.github/workflows/house-review.yml`共用页级计划准备OCR。失败重试标记更新为`house-parser-suite-2026-09-mixed-pages`，旧失败可进入正常重试，当前版本失败仍去重，成功旧缓存不因此强制重放。`backend/tests/test_house_mixed_pages.py`使用生成原生/图像/空白/裁切PDF及固定OCR输出，验证实际CLI文件读写、OCR页子集与坐标、纯输入兼容、原生事实保留、低置信/跨页续行、来源改动拒绝、失败不替换旧文件、保存消费重复一致，并执行工作流安装判定与默认选择器的真实内嵌脚本。验证的是路由与消费契约，不声称新增OCR准确率；未运行线上工作流、补数或生产切换。当前代码与完整回归证据见[当前状态](实现状态与下一步.md)。

计划阶段负责调查实际原件和消费者，分清来源缺失、程序未读、事实冲突、覆盖不足及尚未验证；通过必要的小实验排除假设，选择方法和替代路线。每项实施安排须说明输入、输出、适用范围、依赖、成功标准及失败去向。暂时无法决定的事项留为研究问题，不能写成已经解决。

## 共同假设与研究顺序

### 已选择的原生持仓覆盖路线

原PDF对照确认Harris持仓页3、6、7、8分别有20、20、13、20个非空物理表格行，与已有解析、隔离和排除对象逐格一致；这些页无图像、曲线或表外正文遗漏。剩余6条持仓隔离均为官方明确价值未定，已有45条字段合格持仓。此前持仓0的直接原因是保存输入路径没有生成覆盖证据，不是这45条金融字段未读出。对照产物为`.local/technical-research/holding-inventory-probe.json`。

据此选择：在现有保存输入物化时，从归档原件另做原生持仓表格清点，核对全部页面角色、表格体与已有行对象的完整对应，以及表外正文和非文字内容；将证据交给现有持仓资格和部分报告消费者。字段对象及ID算法保持，缺页、缺行、多表或无法解释的正文仍阻断覆盖。此路线只解决可核对的原生持仓章节，不外推扫描表或整报交易完整性。验收包括真实正常CLI、候选构建与读取器、重复运行，以及漏行/表外文字/图像等反例。

该路线已实现：正常CLI增加45条持仓，原237条交易及源金融行/处置完整对象不变；构建、公开读取、处理器及重复CLI通过。最高HTML基准哈希再次一致，实际人物页45条资产逐项可达，显示6项价值未定及非完整总资产提示。7个无编号空格带复用原生PDF对象级空白检查，修复了源规则面与抽取格边界之间0.0005点舍入造成的匹配失败；容差只用于边界匹配，检查区域仍按原始规则内表面，近边文字反例继续阻断。原生覆盖及封面边界组在干净提交`24aa72e44`通过1825项完整后端检查；后续状态接入单列于P15。证据见E07及`.local/technical-research/backend-verify.log`。

目前证据支持“多个问题共用几何定位、证据角色和覆盖判断”的工作假设，尚不能证明存在一个算法可解决全部来源。推荐先完成下面的研究批次；顺序用于减少无效尝试，不是新的串行审批关卡。

1. **影响与判据核对**：围绕P04、P06、P07、P11、P13列出受影响的固定原件及全部阻断组合，区分官方事实要求、用户决定和算法自设判据。这样能识别哪些修复可实际解锁报告，哪些只减少一个局部报错。
2. **共用方法比较**：围绕P03–P05比较字段定位、读数和覆盖路线；P01及P02中专为连笔日期读取服务的研究按用户决定暂缓。复用失败实验，每个实验预先写清要排除的假设、停止条件和转向依据。P08–P10可同时做只读关系核查，无需等待连笔日期识别。
3. **独立验证及运行条件**：P12确定检查样本，P14–P15确定环境和状态去向；这些条件在方法选择时纳入，防止实验方法到部署时才发现不可用。
4. **形成执行安排**：按共同能力而非逐份PDF拆实现批次，规定正常入口、适用范围、验证和失败回报。方法仍不确定的部分保留研究，不给执行者一个“想办法读对”的任务。P16整体重放与交付在相应能力具备后集中完成。

上述批次是早期研究安排，按用户最新决定改为每轮一个历史失败机制；不把补齐11类原件对应或逐页检查设成下一轮前置任务。后续从历史耗时证据和实际代码选择另一个具体工程卡点，先确定问题边界与验收，再实施接入；已完成机制按其已验证边界复用，不因新样本出现而重复攻关。
