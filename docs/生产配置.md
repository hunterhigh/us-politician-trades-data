# GitHub 生产配置

GitHub 仓库是当前生产环境，不依赖常驻数据库或 Cloudflare。生产数据分为五个分支：

| 分支 | 内容 | 写入者 |
|---|---|---|
| `code` | 代码、工作流、契约、测试和文档 | 维护者开发流程 |
| `main` | 前端读取的规范化快照 | `Publish normalized snapshot` |
| `state` | 来源检查点和最后运行状态 | `House source state`、`Senate identity roster` |
| `evidence` | 官方索引、名册、原始申报文件和获取元数据 | 已启用的来源归档 workflow |
| `review` | 机器抽取、确定性身份、自动资格结果、隔离记录和解析失败 | `House automatic qualification` |

生产 workflow 绑定 GitHub `production` environment。仓库写入使用 GitHub 自动签发的 `GITHUB_TOKEN`，不需要人工创建 Personal Access Token。workflow 只申请 `contents: write`，不会把 token 写入文件或日志。

House Clerk 官方索引和 PTR 下载当前不需要 API key。以下外部密钥仅在对应数据源真正启用后配置为 `production` environment secrets：

| Secret | 用途 | 当前状态 |
|---|---|---|
| `CONGRESS_GOV_API_KEY` | Congress.gov官方历史议员名册，用于补充已离任或名册变动的Senate身份；免费申请 | 未配置，历史身份补充关闭 |
| `ALPACA_API_KEY_ID` | Alpaca 行情身份 | 未配置，行情关闭 |
| `ALPACA_API_SECRET_KEY` | Alpaca 行情密钥 | 未配置，行情关闭 |

不能把真实 Secret 写入 `.env`、workflow YAML、分支、Issue、Actions 输出或生成的 HTML。Fork 和普通 PR 不获得 environment secrets。

`HOUSE_ARCHIVE_BATCH_SIZE` 是 production environment variable，默认建议为 `10`，允许范围为 1–25。它限制每次定时任务最多下载多少份 PDF。工作流每 6 小时运行一次，按顺序下载且每份之间等待 1 秒；单份 PDF 上限 25 MB。

`HOUSE_PARSE_BATCH_SIZE` 控制每次最多解析多少份已归档 PDF，允许范围同为 1–25。`House source state` 成功后会触发 `House automatic qualification`；普通电子PDF只使用固定Python依赖，批次含图片PDF时才安装并调用Tesseract。抽取、资格和隔离产物只进入 `review`，不会自动进入 `main`。

`Senate identity roster` 每日读取 Senate 官方 XML 名册，将原始 XML 和规范 roster 按内容哈希写入 `evidence/senate_efd/members/`，并更新 `state/status/senate_efd.json`。eFD名册本身不需要API token。若production environment存在`CONGRESS_GOV_API_KEY`，同一工作流还会读取Congress.gov官方API的第119届议员数据，按内容哈希归档到`evidence/senate_efd/congress_members/`；身份匹配只在申报日期落入该届国会精确日期和参议员任期时使用这份历史名册，当前名册与历史名册的州、党派或姓氏冲突会失败关闭。密钥缺失时流程继续使用现有Senate名册，不会降低当前生产可用性。

`Senate amendment history plan`只检索受限历史目录并生成候选前件计划，不下载报告正文。`Senate amendment history resolve`在计划形状固定为12个目标、16份候选原件时才下载，先将原件写入`evidence`，再离线解析和正文比较；全部目标唯一匹配后才把12份选中前件作为只读关系证据写入`review/senate_efd/amendment_supplements/`。补充报告不能成为候选交易，也不计入130份当前目录的归档、待处理或1,646笔主输入统计。常规`Senate eFD PTR catalog`每次重建时都会重新验证活动补充指针、原件SHA、当前修订SHA、人物、标题日期、解析器和比较规则。

`Senate paper PTR pages`只处理当前已验证的9份纸面扫描查看器。它要求viewer页面声明连续的`Page N of M`，并只接受`efd-media-public.senate.gov`精确主机下的HTTPS GIF资源；每页校验GIF头、尺寸、字节上限和SHA-256后，按内容地址把图片、元数据及文档清单写入`evidence/senate_efd/paper_pages/`。生产工作流还固定要求9份文档和52页，否则失败关闭。扫描页是OCR与结构化提取的官方输入，不直接进入`review`候选或前端快照。首次生产运行[`35503048508`](https://github.com/hunterhigh/us-politician-trades-data/actions/runs/35503048508)成功，`evidence` commit为`4e8c50a3497f3945a8fc937f4252e09e208d05c7`。

`OGE direct 278-T pipeline`已注册，但`OGE_COLLECTION_ENABLED`与`OGE_TERMS_ACKNOWLEDGED`默认均未配置。定时事件只有在两项production environment variable都精确为`true`时才启动runner；手动触发可在未启用时只记录门禁状态。真正启用前还应配置`OGE_REPORT_BATCH_SIZE`（1–25，建议首次为2），先做官方直链PDF小批次验证。流程只下载目录明确给出的直链278-T，Form 201请求型报告仅计数，不会自动提交请求。OGE不需要API密钥。

`CONGRESS_GOV_API_KEY`由Congress.gov使用的api.data.gov免费签发，不是付费资源。取得密钥后将它写入仓库`production` environment secret，再手动运行一次`Senate identity roster`，成功后运行一次`Senate eFD PTR catalog`。不得使用共享`DEMO_KEY`作为生产密钥，也不得把密钥放进URL、日志或任何Git分支。当前生产窗口从2026-01-01开始，第119届足以覆盖；扩大窗口前必须按所涉届次归档相应Congress.gov名册。

`review/status/house_clerk.json` 提供机器可读的证据总数、成功抽取、失败、待解析及身份建议计数，`summary.json` 暂作兼容别名。存在解析失败时状态为 `attention`，但不会阻止其他合格文档进入自动资格校验；失败文档保留在隔离队列，不写入正式事实。

当前回填阶段两个批量变量均配置为 `25`。依据 [GitHub Actions billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions)，公开仓库使用标准 GitHub-hosted runner 的运行分钟免费；仍需监控 Git 仓库增长和 Actions artifact/storage 用量。生产分支与发布标签已经由 active rulesets 禁止删除和非快进更新。

截至2026-09-21，公开仓库、默认`code`分支、受保护的`production`环境、来源采集变量、Alpaca两项Secret、市场分发授权、100代码行情批次和完整发布开关均已生效。生产运行[`35595705340`](https://github.com/hunterhigh/us-politician-trades-data/actions/runs/35595705340)成功发布`market`提交`d5faa061ab7402e68b18061c0df75e42d5324ec4`和`main`提交`12c2c8e122f3f882fb17d56abfd505cf3d9157f2`，并通过远端四模式回读与冻结前端复验。Alpaca Secret只存在于GitHub环境中，不得写入命令参数、日志、项目文件或任何Git ref。`CONGRESS_GOV_API_KEY`仍是可选的历史身份增强资源，不影响当前首发生产快照。

首次或手动补采可从 Actions 页面运行 `House source state` 并填写 `batch_size`。任务必须先成功推送 `evidence`，再更新 `state`；因此检查点不会声称一个尚未持久化的 PDF 已经归档。

正式快照回退使用 `Rollback production snapshot`，输入目标 `published/<commit>` 的 40 位 commit 和操作前观察到的当前 `main` commit。工作流不会强推历史，而是以当前 `main` 为父提交、用目标快照树创建新的恢复提交，再原子推送新 `main` 和新的 `published/<commit>` 标签。

`evidence` 使用普通 Git 保存二进制文件，便于公开审计和按 commit 恢复，但长期容量效率低。应监控仓库总大小和每月增长；接近 GitHub 容量边界时先暂停归档，再把证据层迁移到保留内容哈希和版本引用的对象存储。迁移前不能删除唯一原件副本。
