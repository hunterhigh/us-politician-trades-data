# 上游报告状态输出契约 v1

日期：2026-10-16。状态：已随 `main=24c3616977625ef3bbac0b2f5888c9572f396248` 正式发布，生产运行和全部分页公开回读通过，见[正式交付证据](上游报告状态正式交付-2026-10-16.md)。最高页面基准仍为用户的 `politician-disclosures (3).html`。本契约增加上游报告处理说明，消费端 Skill 与最终页面由对方实现。

## 一个发布版本中的组成

消费者先固定 `main` 的一个提交，再读取这个提交下的 `manifest.json`。正式交易和报告状态都在同一提交内；清单新增 `disclosure_status`：`schema_version=disclosure-status/v1`、`sha256`、`byte_length`。它指向同提交的 `status/<sha256>.json`。该摘要再引用同目录的报告分页，每页同样声明 SHA-256、字节长度和记录数。摘要及每页最多 256 KiB，合计最多 256 页；超预算报错，不截断。

原有交易 `snapshot_id`、`status_revision` 的含义保留：前者仍是交易／行情发布身份，后者仍是原 `source_health` 指纹。**完整交付版本用固定 `main` 提交识别；详细状态内容用 `disclosure_status.sha256` 识别。**状态单独变化可以形成新提交和新状态指纹，而交易 `snapshot_id` 相同。状态摘要另外绑定同一清单的 `snapshot_id`、`board` 哈希、数据截止日及生成时间，读取时逐项验证。

旧版本没有 `disclosure_status` 时，读取器返回 `None`／“该版本未提供”，不返回零待审。已提供状态的生产目录禁止被普通发布静默降回无状态版本；状态故障在正式分支移动前失败，保留上一次完整发布。是否允许未来以“状态暂不可用”继续更新交易，仍属于执行计划列出的产品决定，本次未开启这种降级。

## 摘要字段

| 字段 | 含义与使用 |
| --- | --- |
| `schema_version` | `disclosure-status/v1`。 |
| `generated_at` | 此完整发布的生成时刻，与清单一致；不是来源最近发现时间。 |
| `provenance` | 固定 `code_commit`、`evidence_commit`、`review_commit`、`previous_main_commit`，均为完整提交 SHA。 |
| `publication` | 同版 `snapshot_id`、`board_sha256`、`data_cutoff_at`，防止把状态贴到另一版交易。 |
| `sources[]` | 按 `scope_id` 分范围的来源状态；同一规范 `source_id=oge` 可有直取、需申请、白宫三个范围。 |
| `sources[].scope` | 报告类型、目录版本／年份和覆盖边界；它决定统计分母，不能略去。 |
| `observed_at` | 该来源已有处理件的观察时刻，可未知；不得用发布生成时间冒充来源刚刚成功。 |
| `limitations` | 来源范围、资格连接或统计中明确存在的限制。 |
| `counts` | 记录数、已识别报告数、身份未知记录数、正式交易绑定数、正式交易未绑定数，及各阶段状态的记录分布。 |
| `pages[]` | 按确定顺序分页的报告账，包含哈希、长度与记录数。 |

当前范围为 `house_ptr`、`senate_ptr`、`oge_direct_278t`、`oge_request_278t`、`whitehouse_public`。House 年报持仓不冒充 PTR 覆盖；已发现的历史索引也不冒充当前年采集已完成。OGE 需申请范围中一条是目录 occurrence，没有唯一报告 ID，所以摘要使用 **record_count**，不把每条称为一份报告。各范围的 `identified_report_count` 也不能直接相加为跨源唯一报告总数。

`publication_transaction_count` 是从**同轮实际准备发布的交易 ID**绑定到报告后计算的数量；`unmatched_publication_transaction_count` 表示该来源正式交易仍无法接到报告账的数量，不叫待审。生成器要求所有正式交易 ID 恰好出现在一个报告或一个未绑定集合中，重复、漏记、跨来源归属错误都会失败。报告的合格行数来自资格件，与正式交易数分别保留，不要求它们靠凑数相等。

## 报告分页记录

| 字段 | 含义 |
| --- | --- |
| `record_key` | 该范围内唯一记录键；House 包括年份，需申请项包括目录快照哈希和位置。 |
| `report_id` | 可信的报告身份；缺唯一身份的目录项为 `null`。House 另以 `document_id` 保留官方报告号。 |
| `document_type`、`source_url` | 来源格式及可回到官方目录／原件的链接；未知链接可为空。 |
| `catalog_state` | `current` 当前选定目录；`historical` 历史保留；`unknown` 无法确认关系。 |
| `acquisition_state` | `archived` 已有受控归档；`request_required` 需申请；`not_archived` 已发现但未归档；`unknown` 未知。 |
| `extraction_state` | `extracted` 已提取；`failed` 当前提取失败；`not_attempted` 未尝试；`unknown` 版本或连接不明。旧失败若已有同版成功，不再算当前失败。 |
| `qualification_state` | `qualified` 有合格内容；`partial` 有合格且有未闭合内容；`quarantined` 尚无合格内容且有阻断；`zero_transactions` 有明确零交易依据；`superseded` 被修订件替代；`not_evaluated` 未评估；`unknown` 无法判定。 |
| `qualified_transaction_count`、`quarantined_row_count` | 资格件可证明的行数；不明或数组不互斥时为 `null`。不能把报告数、物理格和行数相加。 |
| `publication_transaction_count` | 同轮正式交易中能可靠回指此报告的记录数；不代表当前所有原件版本已完整解析。 |
| `publication_binding` | `verified` 已建立报告关系；`unknown` 无法确认。存在正式行绑定时必须 verified。 |
| `source_versions` | 该报告已归档的原件 SHA-256 集合；版本多不算多份报告。 |
| `reason_codes` | 当前阻断、身份／版本未知或已解决关系的可核查原因。一个报告可有多个原因，原因频次不能当报告总数。 |
| `filed_date`、`filed_date_basis` | 可选、日精度的可靠申报日及依据；未知为 `null`。 |
| `catalog_added_date`／`catalog_listed_date` | 可选的来源目录时间，独立保存，不能补成申报日或交易日。 |
| 年报／纸表专属观察 | 可附合格持仓数、无法证明互斥的年报行问题、纸表未知格／未观察页等；必须保留单位与限制。 |

白宫适配器按完整官方 PDF URL 回指其 `wh-url:` 身份；即使旧 `filing_id` 与报告 ID 不同，也不会据此合并不同官方 URL。姓名／类型／年份匹配只能留为候选关系。有合格年报不保证有交易，可能只提供持仓；`publication_binding=verified` 也可来自持仓，是否有正式交易应看 `publication_transaction_count`。OGE 直取有多版原件且资格未绑定某一版时保留未知；不能因历史版合格就声称新版已通过。

## 读取、验证和上游交接

本仓库读取器新增 `PublicSnapshotRepository.disclosure_status(commit, include_records=False)`。`commit` 应使用本次已读取交易的 `snapshot_commit`，不能再次解析移动中的 `main` 后混读。默认只取摘要；`include_records=True` 读取全部分页，验证哈希、字节长度、报告身份唯一、计数守恒和状态分布。原交易 `fetch` 路径继续使用已有四数组和来源健康；新状态引用也随清单元信息传入，不自动变成交易。

命令行：`python -m unison_snapshot fetch-disclosure-status --owner hunterhigh --repo us-politician-trades-data --commit <已固定的main提交> --include-records --output status.json`。旧版输出 `disclosure_status:null`；新版损坏或错版报错，不能按零处理。

生产发布先从固定 evidence／review 和同轮交易候选生成输入账，再附到现有完整快照。预发布远端回读必须带 `--require-disclosure-status`，并核对 evidence／review 提交；全部通过后沿现有原子发布路径切换 main／market。新增只读预演工作流会对完整冻结仓库输入生成并回读状态，但 `published=false`，不采集原件、不执行 OCR、不晋级资格、不移动生产分支。正式上线证据须另记实际运行和最终提交。

## 直接年报的开发扩展

2026-10-22开发分支在同一`disclosure-status/v1`格式中增加按需范围`oge_direct_278e`；此扩展尚未切换生产，不改变上文固定正式版本的交付证据。存在`oge/annual/reports`受控归档时才生成此范围，已有OGE三个范围的顺序保持，消费端应按`scope_id`识别范围。

记录类型为`278e_annual`，归档身份及版本来自现有年度元数据，资格来自`whitehouse/annual/candidate-current.json`中的`oge_annual`审计。交易和持仓的实际准备发布ID分别绑定，已知年报不会伪装成278-T，也不再落进PTR未匹配集合。审计版本不匹配、旧件缺正式ID绑定或没有审计时，资格或合格数保留未知；不是零交易证明。绑定到报告的实际ID不在同版有效资格审计中时，`publication_binding`保留未知并给出原因。

`qualified_transaction_count`和`qualified_holding_count`是已观察合格行数。`observed_annual_row_decision_count`及`observed_quarantined_annual_row_count`明确以年度资格行处置为单位；整报物理隔离总数`quarantined_row_count`继续为null。部分持仓报告的官方价值缺口保留为`partial`，既不冒充完整总资产，也不改变现有交易和持仓事实。
