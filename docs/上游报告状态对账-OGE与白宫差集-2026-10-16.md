## 1. OGE 直取：25 份归档文档为何无正式交易

固定 `review/oge/qualifications/current.json` 有 **336 份直取报告账**，其中 311 份有合格交易，25 份 `promoted_count=0`。这 25 个文档 ID 与[OGE 主账](上游报告状态对账-OGE-2026-10-16.md)列出的“归档减正式有交易的文档”集合完全相同。资格账内部可互斥地分为：

| 25 份的主要阻断组 | 文档数 | 当前可证明的含义 |
| --- | ---: | --- |
| 报告证据不完整、申报日不可用 | 19 | 均同时有 `document_evidence_incomplete` 与 `filed_at_invalid`；其中一份还存在修订关系未闭合。部分报告的提取行另有金额、日期、方向、行号等问题；不能只补申报日就晋级。特朗普 2026-09-17 报告在这一组。 |
| 申报人身份匹配有歧义 | 3 | 报告级 `identity_ambiguous`，现有候选不把来源行归给猜测的人。 |
| 仅剩行级资格问题 | 3 | 一份金额档位不支持；一份金额档位／方向不支持；一份提取 ID 重复或无效。三份都未形成合格交易。 |
| **合计** | **25** | “无正式交易的文档数”，不是漏掉的 25 笔交易，也不是 25 份都未解析。 |

上述归类以 `promoted_count=0` 为筛选条件，按报告级原因优先、再按行级原因归组；不是把多重原因直接相加。资格账内的 OGE 直取合格交易 5,081 行与此固定 `main` 的直取 5,081 行数量相等，但仍需 A4 同轮输入对账才能证明发布关系。资格账 `quarantined_row_count=8,091` 是行数，不能加到 25 份报告上。此审计只分类既有隔离，不替格式解析 B1 下结论。

## 2. 白宫公开目录：身份范围与处理阶段

固定 `review/whitehouse/disclosures/index-current.json` 列出 **365 个唯一 `wh-url:` 文档 ID／公开链接**，对应 `archive-status.json` 的 365 个已归档版本、0 个待归档 URL。目录标签分为 81 个 278-T、97 个年报、16 个离职报告、171 个仅能从标签判断为 278e 但类型未定。标签分类状态为 183 个从标签分类、171 个需看 PDF、11 个官方 IRI 编码 PDF 待处理；这些是目录识别状态，不是生产资格结论。

同一 `review/whitehouse/coverage-current.json` 在这 365 个 ID 上给出：**80 个已提取、仅供审查；282 个已提取但有问题；3 个提取隔离**，合计 365。`whitehouse/extraction-status.json` 的 **373 个选定原件版本**分为 370 个已有提取与 3 个已有失败；373 是版本数，365 是当前链接／文档 ID 数，不能互换。`coverage-current.json` 的 `production_qualified_fact_count=0` 表示这个目录覆盖件本身没有建立正式资格绑定，**不能推断正式生产没有白宫交易，也不能把 365 全称为未过审报告**。

白宫 278-T 的独立 `whitehouse/qualifications/candidate-current.json` 恰覆盖目录中的 **81 个 278-T ID**：38 份有合格交易（27 份只见合格行、11 份还带隔离行），43 份没有合格行；合格交易 **1,650 行**，隔离 **8,643 行**。43 份中的原因会重叠，例如来源提取不完整 26 份、目录位置匹配问题 14 份、版本／修订关系未闭合 13 份，不能把这些数字相加。它另报年报 Part 7 不可比较行 14,617、重叠行 25；这些也不能直接当作待发布交易。白宫年报的资格链另算，不能拿 81 个 278-T 文档替代全部 365 个公开件。

固定 `main` 的白宫官方 URL 有 8,409 条交易、39 个 `filing_id`；其中 6,759 条是年报 Part 7，1,650 条是 278-T。随后的完整固定输入预演逐官方 URL 核对为：**38 份 278-T 提供 1,650 条交易，1 份年报提供 6,759 条交易**，因此有交易的报告恰为 39 份。固定 review 中 29 份合格年报还有只提供持仓的报告；不能把 29 份全算成有正式交易。`publication_binding=verified` 的白宫 67 份包含交易或持仓绑定，也不等于 67 份都有交易。`main` 的 8,409 条已包含在 `source_id=oge` 的 13,490 条内，不能重复相加。当前 365 个链接的旧目录覆盖件未绑定正式资格；新适配器现已按 URL 单独连接，旧覆盖件本身仍不改写。

`whitehouse/disclosures/crosswalk-current.json` 还只对 **120 个 OGE 需申请目录 occurrence**尝试白宫公开链接的候选匹配；其 `matching_note` 明说姓名／类型／年份匹配不是报告身份核验，也不是 Form 201 申请已履行。因此 120 不能从 OGE 的 4,761 个需申请 occurrence 中扣除，更不能视为 120 份已经取得的同一报告。

## 3. 对状态产品的直接约束

1. OGE 直取可按文档 ID 输出“归档、提取、报告资格、合格行与隔离行”；25 份零正式交易要带具体原因组，不输出一个含糊的“漏发 25 份”。
2. 白宫公开件先把 365 个目录 ID 与原件版本／提取阶段列出，再分别接 278-T 和年报资格链。目录覆盖件的 `production_qualified_fact_count=0` 是**连接缺失**，不是全体零合格。A4 前必须建立可复算的正式 URL／`filing_id` 到公开文档 ID 的映射，并记录未匹配项。
3. 需申请 OGE occurrence 与白宫公开件仅保留未核验候选关系；产品不宣称其为同一报告。跨源总“待审文件数”继续未知。
4. A4 生成正式状态时，使用同一轮固定来源输入及 `main` 准备提交重算发布关系；本轮不同时间提交仅作为现状调查。任何状态输出不能将提取行写入正式交易。
