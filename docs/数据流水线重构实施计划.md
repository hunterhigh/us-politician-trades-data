## 1. 目标、基准和范围

本轮产品目标是让**用户指定的最新 HTML 正确消费完整、可追溯、语义可靠的披露与行情数据**。治理迁移是达成这个目标的后端手段；旧数据无损承接是切流保护条件，不能替代页面结果验收。既有正式事实不能因为新的影子解析器未覆盖某种文档而消失。来源采集和解析的质量改进继续做，但不以全量历史 PDF 重新扫描、OCR 或重解析作为治理切流的默认前提。

**ID 规则校准（2026-10-08）：** G0/G1 的旧正式 ID 守恒是一次性迁移审计，不是永久发布契约。常态发布只比较相邻两次规范快照：同一 ID 的事实直接延续，新增事实须有来源资格；重编号须有唯一的旧→新映射和核验过的官方证据，原 ID 不留在新五数组中；修订或撤回也须有针对该来源的证据和差异决议。无法解释的消失或字段变化阻断发布。发布差异报告只记变化与汇总，不逐轮复制所有旧 ID。此前本地未合入的“每轮永久保留所有历史正式 ID”门禁作废，不得推送或切流使用。

### 两条工作线

| 工作线 | 本轮交付 | 与切流的关系 |
| --- | --- | --- |
| A. 前端驱动的治理迁移 | 固定 HTML 页面/字段/空值验收矩阵；旧候选与来源证据逐条绑定；统一账本与处置；确定性五数组投影；页面、新旧差异、发布和回滚门禁 | 本轮关键路径。旧合格记录可经已验证的旧抽取和资格结果迁移，不要求重跑 OCR；以页面实际结果判断是否达成产品目标。 |
| B. 来源质量 | 新发现物理漏行、OCR 漂移、身份、修订、证券映射和纸面报告等定向修复 | 独立队列。只在具体问题否定拟迁移事实、证据或资格时阻断该记录；不让尚未合格的新行阻断所有旧记录。 |

两线共享来源标识、证据和隔离状态，但不能把 B 的试验结果直接覆盖 A 的固定事实。现有旧记录也不因“曾发布”就无条件通过：需要可核对的旧候选 ID、资格结果、字段、来源/抽取版本及证据引用。原件字节本轮未复核时如实记录已存档哈希和验证层级，不能写成已重验。遇到真实字段冲突或来源身份无法闭合，先记录待核并继续不受影响的候选构建，在最终放行前逐条调查和阻断未决项；不得把 simulated 改标 official_matched，也不得伪造缺失值。

**2026-10-08 用户顺序决定：** 先完成新投影接入并送入现有构建器，生成完整候选和差异清单；实施中遇到缺失证据、字段冲突、原件版本疑点，先逐条记入待核清单，保留已确认事实和既有隔离状态，继续完成不受影响的构建与页面检查。最后才按清单定向核验。待核项不能靠猜测晋级，也不能在正式切流时被静默删除；最终发布门禁仍对影响正式事实的未决差异失败关闭。全量重扫不因此成为前置步骤。

## 3. 修订后的实施顺序与放行件

### G0 固定前端验收基准与输入清单

先以最新 HTML 固定页面、字段、关联键、窗口时钟、排序、详情链接和缺失值验收矩阵，标出每项由哪一组规范数据或页面派生值提供。固定六个分支提交、生产 manifest、现有三个来源候选文件、review 抽取/资格产物、evidence 元数据、HTML 哈希和市场提交。生成旧正式五数组的机器可读清单：交易、持仓、人物按旧 ID 唯一，行情与来源健康按快照键和固定市场提交对账；每条事实列出来源、申报/人物、规范字段、证据引用、原资格规则及输入对象哈希。来源字节确未重新读到时标注 `archived_hash_not_reverified`。保持原始主工作区的既存未提交改动，不覆盖 `review-input/`。

**G0 放行件：** 最新 HTML 的看板、30/90 日交易和披露窗口、人物页、股票页、详情抽屉、来源区、行情图及空状态均有可执行的验收项；旧处理器和交接包只作兼容对照，不裁定与 HTML 冲突的行为。新旧快照比较使用同一固定时点与版本。

### G1 统一旧事实与账本桥接

沿用已闭合的 9,742 条绑定，并将白宫 PTR 1,391、年报 6,759、其他 OGE 124 的固定旧抽取/候选对账纳入同一机器门禁。为 Senate 纸面旧候选 1 条建立来源绑定；若无法确认，保留在旧路径并作为该条阻断，不能从新投影静默删除。桥接记录必须区分 `legacy_qualified_binding` 与新解析产生的 `qualified` 观察值，记录原资格及证据链，不把旧结论冒充新 OCR 结果。跨文档重复/修订保持既有可信决议；新证据有冲突时逐条隔离并记录差异。

**G1 放行件：** 先证明历史 18,017 条交易完整保留，再对切流前固定的**当前正式快照全量 ID 集合**逐条给出唯一的“迁移绑定、明确保留于旧路径、或有证据的修订/撤回”处置；截至本次复核，该集合为 18,086 条交易、5,595 条持仓、394 人，后续若生产更新须重新冻结。交易、持仓和人物各有独立的来源/资格/ID 覆盖账，不以交易覆盖率代替其他集合。29 条持仓的旧新 ID 与来源 URL 变化须另建有证据的重绑定映射，核对原件哈希及文档关系；字段配对或净数量相等均不算闭合。切流所需的新投影最终不得依赖“保留于旧路径”占位；该状态仅用于避免过早删除和定位阻断。所有新增影子行与旧数据分开计数。

G1 覆盖率是防止数据丢失的保护条件，不是前端交付完成率。覆盖账须同时标注记录进入 HTML 的哪些页面、无 ticker/行情时如何显示、证据链接是否可用；不能只凭总数相等放行。

### G2 确定性候选与前端投影

用桥接结果和现有来源资格规则生成完整五数组候选：人物、交易、持仓、行情与来源健康。复用原候选 builder 的人物、申报时间、持有人、证券、期权、修订和去重规则；ledger 只提供来源观察和证据，不能直接填充这些缺项。所有旧正式交易和持仓均按 ID/字段比较；允许的差异必须有单独决议和对应前端影响。未知 ticker/价格保持 `null`，收益不可计算保持 `null`。输出快照前检查唯一 ID、引用完整性、来源健康、数据截止和市场固定提交。

**G2 放行件：** 旧正式 ID 无静默减少、字段差异无未解释项，新增记录只来自独立通过资格的来源；按 G0 矩阵逐项核对 HTML 实际依赖的字段和派生值。交易窗口按 `transaction_date`，近期披露按 `filed_at`；30/90 日 `market_moves` 与价格历史使用固定行情版本；无 ticker/价格/收益显示页面允许的空状态，金额未知不能变为 0，来源健康的“检查”不能冒充“成功同步”。七个缺事件日行情的收益必须为 `null`/“—”。体积/重复数组优化只有在消费代码确认无兼容损失后再做，不占据切流关键路径。

另有一项后续产品规则尚未落地：仓库记录用户决定“已核实来源先更新，逐处标明最后更新时间”。当前生产仍采用三源共同完整日和两天水位差门禁；当前 HTML 的来源卡显示来源时间，其他区域使用统一截止时间。若要改为来源级独立放行，先定义各页面/统计窗口的数据截止、陈旧提示、旧事实保留和 `source_health` 状态语义，再按最新用户决定与 HTML 实际行为处理差异；不能只放松水位常量或把某源最后检查时间写成成功同步时间。此项属于后续扩展，不把 10 月 8 日的共同截止发布误记为已实现。

### G3 只读影子、任务闭环与发布准备

在固定输入上重复构建，比较内容哈希、行处置、候选 ID/字段与五数组；核对手动、定时、失败重试的幂等和现有 writer lock。影子产物仅写隔离路径，不写生产 `main/market`。用最新 HTML 实际页面代码和浏览器按 G0 矩阵核对 dashboard、两个时间窗口及其不同日期口径、search、person、ticker、交易详情、来源状态、行情和空值；旧处理器/交接测试只记录兼容影响，不能把其通过当作 HTML 已通过。验收旧 `main/market` 固定提交可读、发布失败不移动指针、回退不依赖重新采集。

复用现已进入 `publish-complete.yml` 的指定 HTML 固定模板与发布前/准备提交回读后的浏览器门禁；继续补齐 G0 矩阵的具体断言，尤其是七个收益空值、两种窗口时钟、来源时间和新增记录的页面可达性。现有门禁只验证过旧生产路径，不证明 vNext 投影完成。手动成功还须与至少一轮真实定时采集、下游资格及发布的终态分开记录。

### G4 受控切流与观察

只有 G0 前端矩阵、G1–G3 机器报告和实际页面验收均通过，才让现有唯一完整发布工作流读取新候选；发布前后分别固定和回读 `main/market`，保存对应标签和快照哈希。先保留旧候选构建和回滚入口，观察实际增量运行及差异；出现数据丢失、身份/来源错误、前端语义倒退或重复写入时，按固定已发布提交回退。切流后再讨论旧路径退役和 cron/传输优化。

## 4. 来源质量队列的处理规则

House 失败扫描件与漏行、Senate 纸面格位、OGE 年报 Part 7、OGE 85 条身份/重复异常、白宫 OCR 漂移等按来源、文件和记录单独立项。每项保存固定原件/抽取哈希、页/行/格证据、旧候选关系、处置原因和复核后的新规则。可证明的新事实经现有资格和去重门禁后增量进入候选；仍有歧义的事实继续隔离。不可用的实时来源或 OCR 环境不得触发对旧合格事实的撤回。若某项发现证明旧正式记录本身不可靠，则对该记录执行专项调查和有证据的修订决议，暂停它的迁移或发布；不以此推断全站迁移失败。
