# 当前目标与优先级

生效日期：2026-09-21
状态：当前执行基线

本文是项目当前工作的最高优先级说明。它覆盖《政客交易数据服务-总体设计 v0.3》《实现状态与下一步》及旧复核流程中与以下决定冲突的内容：取消逐条人工复核和具名人工批准作为生产晋级条件；停止把空快照或单一来源试点当作产品交付终点。

## 唯一当前目标

在不修改对方生产前端业务功能和数据含义的前提下，完成其要求范围内的披露数据与行情数据回填，生成完整候选快照，使用对方实际处理器、测试和渲染器完成端到端验收，然后原子发布为正式 `main`。

当前 GitHub 仓库、Actions、`state`、`evidence`、`review`、发布和回退能力是实现该目标的后台基础设施。它们本身不构成产品完成；`main` 仍为 `bootstrap_empty` 时，不得声称前端生产交付完成。

## 已确认的产品原则

1. 对方前端是验收目标。后端、数据布局和读取层适配前端，不要求前端为当前后台骨架删减功能。
2. 取消全量逐条人工复核、具名复核者和逐条人工批准门禁。已有人工复核命令和模板降为异常调查工具，不再阻止符合自动规则的标准记录发布。
3. 标准记录由确定性自动规则晋级。解析不确定、OCR置信不足、身份冲突、修订关系不明、金额语义无法表示或证据不闭合的记录进入隔离队列；隔离记录不阻塞其他合格记录。
4. 人工抽样审计可以用于评估解析质量，但不是每条记录的生产前置条件。来源用途和行情再分发许可仍属于项目级发布条件。
5. 不伪造缺失字段、价格、收益或覆盖范围。无法支持的数据必须明确标记缺失、隔离或不覆盖。
6. 完整候选快照先通过前端验收，再移动正式 `main`；生产发布保留固定 commit、内容哈希、发布标签和回退能力。

## 自动晋级规则

一条披露记录只有同时满足以下条件，才能自动进入候选事实：

- 来自约定的官方来源，并能定位到已归档原件、来源 URL 和 SHA-256；
- 解析器版本固定，文件版式属于已通过黄金样本验证的类型；
- 人物由官方稳定标识或无歧义规则确定，不能只依赖姓名猜测；
- 日期、交易类型、资产、金额语义和证券标识通过 schema 与业务校验；
- 修订、撤回和 amended 关系能够由确定性规则建立；无法确定时隔离；
- 去重、外键、证据引用和内容哈希检查通过；
- 没有静默丢行、截断或用默认值掩盖解析失败。

自动规则通过后，系统直接产生可进入候选快照的规范事实，不再要求 `reviewer`、`reviewed_at` 或逐行人工决定。任何规则失败都必须留下机器可读原因、原件引用和重试状态。

## 项目优先级

| 顺序 | 工作 | 完成结果 |
|---:|---|---|
| P0-1 | 固定前端验收基线 | 交接包与交接说明共同作为唯一基线；固定现有前端、处理器、渲染器和契约要求，不等待另一套前端；只记录本项目实际运行的测试 |
| P0-2 | 完成披露回填 | 按前端契约要求的来源和时间范围完成 House、Senate、OGE 等官方数据；所有文件有已解析、隔离或明确排除结果 |
| P0-3 | 完成自动解析与OCR | 修复特殊金额、跨页交易和身份规则；为图片 PDF 增加有界 OCR；标准记录自动晋级，异常进入隔离队列 |
| P0-4 | 完成行情回填 | 为所有可识别证券补齐前端需要的价格、基准、公司行动和表现数据；使用允许本项目公开生产用途和再分发方式的数据源 |
| P0-5 | 构建完整候选快照 | 五组前端数据、覆盖信息、来源健康和证据引用通过确定性、完整性及交叉引用检查 |
| P0-6 | 原前端端到端验收 | 看板、人物、股票、证据问答、图表、跳转、无数据语义、加载时间及全部随附测试通过 |
| P0-7 | 正式发布 | 候选快照原子发布到 `main`，生成 `published/<commit>`，完成生产读取检查和回退验证 |

P0工作完成前，以下事项降为后续或仅在阻塞P0时处理：Cloudflare、在线数据库、界面重写、空快照美化、独立D阶段文书、逐条人工复核工具扩展以及不影响前端验收的架构优化。

P0-2 至 P0-6 允许增量交叉推进：已经自动合格的真实 House 数据应尽快组成非发布候选快照，提前运行原前端集成验收；不必等待所有来源回填完才第一次接前端。正式 `main` 仍需满足完整完成定义。

## 当前完成定义

只有同时满足以下条件，当前目标才算完成：

- 对方前端代码无需业务删减或临时假数据即可运行；
- 前端要求范围内的披露来源和时间窗口已经回填，未处理记录全部有可见状态；
- 前端需要的行情覆盖完成，许可与技术分发方式相符；
- 自动晋级和隔离机制替代逐条人工审批，并通过真实黄金样本与回归测试；
- 完整候选快照通过对方实际测试和四类业务入口的端到端渲染；
- 非演示、非空的正式快照发布到 `main`，固定版本可读且能够回退；
- README、运行状态和前端展示准确说明来源、数据截止时间、覆盖范围与缺失项。

后续实施、测试、文档和资源决策都应先回答：它是否直接推进完整数据、行情和原前端验收。不能推进该目标的工作暂缓。
