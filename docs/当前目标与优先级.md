# 当前目标与优先级

## 目标与当前主线

交付相比旧版有可核实改进、可维护且可自动运行的后端能力。原35项交付和11类输入保持；不以恢复交易条数、局部测试或提交数量计算产品完成度，不开展逐份补数。

2026-10-27用户要求重构计划只列已有调研依据、方法和验收明确的执行动作，减少在无可行方法的问题上反复消耗。实施队列与尚未解决的研究题分开；未解决项仍对应原T/K编号，不隐式删减范围或冒称完成。动作可以确定执行，不能预先保证验收一定通过。

## 两线程分工

- **流水线技术规划**：承担剩余方法未知的调查、区分方案的实验和相应机制实现，交付代码、输入/输出约定、适用限制、正常入口正例及错误接受反例。House有界原生修订来源守护和正常superseded发布链已在`441e8830e`实现，适用限制及正反证据见当前状态；其他扫描目标/修订源关系仍需方法，不能据此签整个K10。
- **流水线重构（本线程）**：承担旧版对比、接收已验证方法、正常入口集成、兼容和失败恢复检查，以及对原35项的交付收口。实施前查现有代码和回执，不重复研究另一线程的问题，也不把研究题直接改写成“解决某类问题”的指令。
- 两线程共用工作树；正在开发的文件由开发方维护。本线程用明确提交的干净源码快照做比较，保留现有未提交修改，避免验证结果混入冻结裁切/未完成编号证明。读取另一线程不等于已向其派工或获得交付确认；跨线程消息仍需用户授权。
- 接收时只需要已有提交和证据入口、接口及限制、具体命令/预期结果；缺方法正证的事项留在研究侧。依赖该方法的单项等待，独立的已确定动作继续。

## 有效边界

- 最高前端基准为根AGENTS指定的最新HTML，旧方案冲突时以它及用户后续批准的产品口径为准。
- 交付仍需完成模块实现、正常入口集成、兼容性、失败恢复和受控发布验证。历史T02–T22中的固定样例要求是相应能力的验证材料，不再据此逐份恢复数据或阻止独立产品代码改造；T23全量重放及生产切换仍未开始。先完成关键技术判断，再实现及验证，不增加例行审批流程。
- 当前不提前全量补数、重采集或切换生产。固定5页Paddle试验仍由用户暂停，不自行重试、轮询内存或关闭应用。
- 2026-10-23用户明确连笔日期先不处理：已核实当前未解决，本轮列为明确不解决、暂缓项，移出当前攻克和方法比较安排；不继续日期识别模型、分割或专为该识别服务的定位实验，用户明确恢复后再处理。既有已验证蓝墨日期能力保留。受影响报告继续如实保留日期未知及资格阻断，不替换日期、不算解决；其他问题继续推进。
- 普通范围内技术选择由Codex承担；改变产品承诺、范围、显著费用或用户暂停决定时才讨论。

## 已批准产品口径

- 按官方披露行计数；同资产不同账户分别保留并显示账户标题。可靠官方归属足以确定申报人，不另设签名字形门槛。不得猜日期、金额、owner或制造冗余正式ID。
- 七个早于可验证行情的事件收益保留null，页面显示“—”。
- 交易及持仓的有限金额与开口金额分开展示、汇总；开口保留阈值与未知上限，计入条数，在金额排名中单列，不伪造上界。
- 六列表未说明owner可显示Undisclosed；House新解析纸表原件确实留空时亦适用。读不清/冲突不是留空；不自动扩展到House电子表或年报默认值，旧正式owner纠正先列差异。
- 完整可靠持仓章节仅因官方明确价值未定形成缺口时，可展示已知项并提示部分报告。适用于已批准的House及OGE情形，不混报告、不冒充完整总额，不放宽缺页、未读或冲突。
- Senate年报Part4b、House Schedule B、OGE Part7按独立披露行展示、计数；跨报疑似重合标注，已证明的副本/修订仍去重。
- 允许有源依据的旧事实纠错与唯一映射重编号；无法解释的丢失或变化阻断相关发布。
