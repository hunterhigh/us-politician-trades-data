# House PTR 扫描报告页级门禁风险审计

日期：2026-09-30。结论：**暂不实现或启用通用失败关闭规则，也不触发生产重试。** 当前 OCR 词与现有版式几何不能可靠证明文件全部物理交易行得到处置。仅对旧失败文件做新增重试门禁，与回溯处理已成功文件，是两个不同决策；前者不得自动改变后者的既有候选。

## 固定样本及计数方法

- 最新前端 HTML `politician-disclosures (3).html` 的 SHA-256 再次核对为 `D60282832DC0E38E47BE900FDD37AA386DB474DF404989467FFB8B55367EFAA4`。
- 官方原件固定在 `evidence` 提交 `5fe5f0adb3181c5d1552dff3f07336464c3043a7`；存档抽取、资格与候选固定在 `review` 提交 `a814fde2bb9664c2b97981a32ce86ab9b3daf223`；隔离解析代码为 `codex/house-ocr-recovery` 提交 `c2e28d875b770e60082f189bc87ac83301ad18b8`。403 份原件逐份复算来源 SHA-256；其中 47 份需要 OCR、356 份有原生词层。运行环境：Python 3.11.9、pdfplumber 0.11.9、Tesseract v5.4.0.20240606，`PYTHONUTF8=1`。
- 47 份 OCR 原件重新抽词，逐页将词坐标归一到宽高。审计代理信号为：`x` 在页面宽度 35%–58%、`y` 在高度 30%–96% 的 OCR 词，能解析为申报年或前一年完整日期（`exact`），或含相应年号/两位年份片段（`fuzzy`）；与已抽取行的页号和纵坐标相差小于页面高度 1.5% 则视为已配对。窄列对照使用 `x` 35%–46%。这是**风险测量代理**，不是已验证的交易行检测器；宽列也包含通知日期，模糊年份可能来自非交易文字。
- [47 份逐文档信号明细](house-ptr-ocr-page-signals-2026-09-30.csv)列出来源哈希、存档/本机状态与行数、既有与本机候选数、表头检测页数和未配对词数。脚本只读取固定 Git blob 或经 SHA-1 验证的只读缓存，不写 `evidence`、`review`、正式候选或生产分支。

现行 `_headed_legacy_table` 是为特定续页版式设置的严格几何识别，只在 47 份中的 `9115704`（两页）和 `9116146`（一页）返回真。它不能被反用为“其他 45 份均未知或不完整”的通用证明。例如 `9115762` 的原件明确写出无交易，已被 TSV 修复验证为成功零行，但同样不满足这个表头谓词。

未配对日期/年份词对漏行敏感，却不能用词数代替物理交易行数：通知日期常被重复计入，同一行可有多个词，表头和样例日期也会出现。长扫描表有单份数百个未配对词。现有 26 份存档成功 OCR 报告中，宽完整日期代理会重新拦下 16 份；尚未逐份视觉闭合，不能把这 16 份一概判定为真的不完整，也不能直接撤下它们的候选。

## 重试边界与所需能力

固定存档 21 份 OCR 失败文件中，本机解析仅有 `9115704`、`9116260`、`9116326` 三份转为返回成功。上述宽完整日期代理和严格表头代理均会保留 `9115704`、拦下后两份；若**只作为旧失败文件的重试前评估**，不会撤下现存正式候选。然而这只是在 21 份已知失败原件上的筛查结果，不足以证明未来扫描版式的文件行完整，也覆盖不到已被存档误标成功的 `9115813` 和 `9116290`。故目前不把它接入重试流程。

后续需要按页检测实际表格网格和每条有内容的物理行，独立识别交易日期列、通知日期列及勾选格；对 OCR 词按检测到的行和列重排，逐行给出“合格、隔离、无法读取”的处置，并核对物理行数与处置行数守恒。日期或勾选格无法可靠识别时应使**该文件**失败关闭。先用 `9116260`、`9116326`、`9115813`、`9116290` 的固定图像，以及 47 份 OCR 全量对照验证，再考虑仅在旧失败重试路径启用。已成功报告的历史候选保留与修订需另有明确迁移策略；这次审计没有改变它们。
