# 开发维护约定

## 代码与数据

代码仓库保留 Python 生产器、公开GitHub读取器、可选Worker、契约测试与合成样本。同一个公开仓库用 `main` 发布manifest和分片，用 `evidence` 按 SHA-256 保存官方原始证据，用 `state` 保存可恢复检查点，用 `review` 保存未复核机器产物。原始供应材料只读；更新时记录来源版本和 SHA-256，先比较契约差异再更换处理器固定值。

开发从默认 `code` 分支建立短分支并通过 PR 合回；`main` 专用于正式数据快照，只接受发布 workflow 的追加提交。代码使用语义版本；数据以 snapshot_id 与 Git commit 标识，两者不得混用。公开远端仓库已配置 active rulesets：`code/main/state/evidence/review` 和 `published/*` 禁止删除及非快进更新。

Fork 不携带 Secret 或生产自动同步权限。PR CI 只读 contents，不使用 pull_request_target 执行外来代码。生产任务只在指定上游仓库及 `production` environment 中开启；每个数据分支仅一个写者。事实发布前确认远端头未变化，并原子推送分支与发布标签。正式事实发布保持手动；House 官方索引、原件归档和检查点每 6 小时运行一次。

## 每次改动

运行 backend/scripts/verify.py 和 gateway 的测试、类型检查；修改契约时补充反例与原包处理器联调。不要在离线 CI 拉真实上游数据。对规则破坏、数据质量失败或未获准来源直接停止发布，保留上一版。

House PTR 解析结果只进入待复核队列。转为 `official_matched` 前，复核文件必须绑定原件哈希与解析器版本，确认官方 BioGuide 身份、来源使用批准、申报时间归一方式和每一行的接受/拒绝决定；更正或拒绝都要写原因。复核文件应通过普通 PR 审查，自动任务不得填写复核人或来源批准。

## 回退与恢复（本地已验证）

在 backend 中设置 PYTHONPATH=src 后：

```powershell
python -m unison_snapshot rollback-demo --store ../.local/demo/snapshots.git --target <历史已发布SHA> --expected-head <当前SHA>
```

这只移动 demo 分支，保留发布标签及历史数据。真实服务回退尚需实现 main 的对应受控流程，不能照搬 demo 命令到生产。

独立备份示例（在根目录）：

```powershell
git --git-dir=.local/demo/snapshots.git bundle create .local/demo-backup.bundle --all
git clone --bare .local/demo-backup.bundle .local/restored.git
```

恢复验收必须按原 commit 重新组装并比较内容；测试已有此演练。当前仅手工本地备份，不构成异地灾备。上线前补齐存储位置、保留期、责任人和定期恢复频率。

## 费用与运行边界

当前有离线 CI、手动事实发布和每 6 小时一次的 House 证据归档；未开启自动付费资源。归档任务每次最多处理配置的小批量 PDF，并记录实际运行分钟和 `evidence` 分支增长。GitHub 仓库接近容量边界时必须暂停归档并迁移证据层，不能静默丢弃原件。
