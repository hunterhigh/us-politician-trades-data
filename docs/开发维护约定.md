# 开发维护约定

## 代码与数据

代码仓库保留 Python 生产器、公开GitHub读取器、可选Worker、契约测试与合成样本。同一个公开仓库用 `main` 发布manifest和分片，用 `market` 保存经许可的内容寻址行情并由`main`固定引用，用 `evidence` 按 SHA-256 保存官方原始证据，用 `state` 保存可恢复检查点，用 `review` 保存解析、资格、异常与候选产物。原始供应材料只读；更新时记录来源版本和 SHA-256，先比较契约差异再更换处理器固定值。

开发从默认 `code` 分支建立短分支并通过 PR 合回；`main` 专用于正式数据快照，只接受发布 workflow 的追加提交。代码使用语义版本；数据以 snapshot_id 与 Git commit 标识，两者不得混用。2026-09-22已核对公开远端的 active rulesets：`code/main/state/evidence/review/market`六个分支和`published/*`、`published-market/*`标签禁止删除及非快进更新。

Fork 不携带 Secret 或生产自动同步权限。PR CI 只读 contents，不使用 pull_request_target 执行外来代码。生产任务只在指定上游仓库及 `production` environment 中开启；每个数据分支仅一个写者。事实发布前确认远端头未变化，并原子推送分支与发布标签。完整发布已配置工作日定时与手动触发；2026-09-22首次定时作业被旧环境开关条件跳过，修复后的无人介入连续成功仍待实际定时运行核验。来源工作流按各自有界批次运行。

## 每次改动

修改行为后运行相关测试；涉及生产器时运行 `backend/scripts/verify.py`，涉及Worker时运行`gateway`测试与类型检查。修改消费契约时补充反例并用冻结交接包处理器联调。不要在离线 CI 拉真实上游数据。对规则破坏、数据质量失败或未获准来源直接停止发布，保留上一版。

House PTR 解析结果先进入资格队列。自动任务必须绑定原件哈希与解析器版本，使用无歧义的官方 BioGuide 身份，并对日期、金额、证券标识、修订关系和证据引用执行确定性校验；合格行转为 `official_matched` 候选，失败行写入机器可读隔离原因。旧人工复核文件仅用于调查异常，不是标准行晋级条件。

## 回退与恢复

在 backend 中设置 PYTHONPATH=src 后：

```powershell
python -m unison_snapshot rollback-demo --store ../.local/demo/snapshots.git --target <历史已发布SHA> --expected-head <当前SHA>
```

这只移动 demo 分支，保留发布标签及历史数据。真实`main`的受控回退工作流已实现并演练；生产回退应使用 `.github/workflows/rollback.yml` 的环境门禁与目标提交检查，不能照搬 demo 命令。

独立备份示例（在根目录）：

```powershell
git --git-dir=.local/demo/snapshots.git bundle create .local/demo-backup.bundle --all
git clone --bare .local/demo-backup.bundle .local/restored.git
```

恢复验收必须按原 commit 重新组装并比较内容；本地 bundle 测试已有此演练。GitHub内发布标签与回退路径不构成异地灾备；外部备份、保留期和定期恢复仍待实现。

## 费用与运行边界

当前有离线 CI、来源增量、工作日定时完整发布与手动发布；行情增量缓存已通过三次手动生产运行，实际工作日消耗仍待观察。归档任务每次只处理配置的有界批量，并记录实际运行分钟、API页数和数据分支增长。GitHub 仓库接近容量边界时必须暂停归档并规划证据层迁移，不能静默丢弃原件。
