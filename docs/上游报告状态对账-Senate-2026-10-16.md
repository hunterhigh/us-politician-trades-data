## 本轮差集与状态产品的限制

1. **无当前目录到原件缺口**：135 个当前 UUID 都有归档路径；但目录外的 16 个历史归档 UUID 不能自动计入当前待审，其中 4 个与已解析修订链未关联。
2. **当前提取缺口明确**：3 个纸表 UUID 缺 v2 提取，已有对应本版失败件。`report_failures/` 的 14 个旧失败 UUID 与当前成功提取重叠，不能再算失败。
3. **资格不能压成一个“未过审报告数”**：14 份整件隔离、5 份仅行隔离、4 份部分合格、4 份当前目录内被替代、3 份提取失败，代表不同阶段和关系；其中“部分合格”已贡献正式交易。
4. **正式已发布与 review 现状须双时点呈现**：正式 `main` 是 1558 条、109 份；本次 review 虽与其 ID 集一致，却生成于 `main` 之后。未来状态产物必须引用构建时真正冻结的 `evidence`／`review`／`main` 坐标，并标出观察时间。
5. **需要保留未知**：目录外、非已解析修订链的 4 份归档无法据这轮证据归类；纸表还有未知格和未观察页。任何统一状态摘要都应明确覆盖范围及这些未知，而不能以零代替。

## 复算方法

所有集合只读自上述固定提交。可用 `git ls-tree -r --name-only <commit> senate_efd/...` 列路径，不使用会移动的分支名；`git show <commit>:<path>` 读 JSON。此工作树为 partial clone，某些 Git blob 未在本地，`git show` 曾触发 Git transport 连接失败；目录 manifest 与 discovery 使用 `gh api repos/hunterhigh/us-politician-trades-data/contents/<path>?ref=<固定提交>` 读取同一固定对象，核对内容路径／哈希，不使用浮动 `main`、`review`。具体计算如下：

```text
C = discovery.reports 的 document_id 集；按 access_method 分电子／纸表。
A = evidence/reports/*/*.metadata.json 的 (document_id, source_sha256) 集。
P = evidence/paper_pages/* 的 document_id 集。
X = review/extractions/*/*/senate-efd-report-parser-2026-09-v2.json 的 (document_id, source_sha256) 集。
F = review/paper_report_failures/*/*/senate-efd-report-parser-2026-09-v2.json 的 UUID 集。
Q/R/L = qualifications/current.json 的 qualified_rows／quarantined_reports／quarantined_rows 的 UUID 集。
S = resolved_amendment_chains 中 superseded_document_ids 的 UUID 集。
M = main 清单所指 board 中 source_id=senate_efd 的交易 ID 与 filing_id 集。
核对 C ⊆ A.UUID，C-X.UUID=F，X ⊆ A，X.UUID=Q ∪ R ∪ (L-Q) ∪ (S∩C)，以及 M.ID=qualified_rows.transaction_id。
```

这里 `X.UUID` 的四类互斥集合大小分别为 109、14、5、4。该式仅针对本次固定目录和本版提取器；目录外归档及其他版本提取仍保存，不能因未落在当前集合就删除。
