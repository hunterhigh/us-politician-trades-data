# US Politician Trades Watch

Use the latest successfully refreshed database snapshot to report disclosed activity by members of Congress, the President, Vice President, and covered senior executive officials. Attribute every material claim to a filing or source record.

## Required runtime

Resolve paths relative to this `SKILL.md`; never assume an installation directory.

```python
from pathlib import Path

SKILL_ROOT = Path(SKILL_MD_PATH).resolve().parent
FETCH_SNAPSHOT = SKILL_ROOT / "scripts" / "fetch_snapshot.py"

QUERY_SNAPSHOT = SKILL_ROOT / "scripts" / "query_snapshot.py"

```

`POLITICIAN_DATA_API_URL` identifies the remote data service. `POLITICIAN_DATA_API_TOKEN` is optional when that service is public. Read credentials only from the environment; never ask the user to paste a token, print it, or write it to the Skill directory.

The remote service, not the Capafy Skill process, owns `ALPACA_API_KEY_ID` and `ALPACA_API_SECRET_KEY`. It must request Alpaca historical bars with `feed=sip`, `timeframe=1Day`, and `adjustment=split` explicitly. Never expose those credentials in the snapshot.

Use a temporary directory for each user message. Capafy-local files are disposable caches, not the database of record.

## Route every request

Treat each user message as a new freshness boundary.

1. Detect the request mode.
   - No concrete person, ticker, date, filing, or comparison: `dashboard`.
   - One person: `person`.
   - One ticker or company: `ticker`; include both latest reported holders and disclosed transactions.
   - Multiple people, tickers, parties, chambers, or a stated period: `search`.
2. Request an incrementally refreshed snapshot from the data API, scoped as narrowly as the question permits. A request containing “latest”, “today”, “just now”, or an equivalent phrase sets `force_refresh=true`.
3. If refresh succeeds, answer only from the returned `snapshot_id`.
4. If refresh fails but the API supplies a last-successful snapshot, use it and state its exact cutoff and the failed source. Never label fallback data as current.
5. If no usable snapshot exists, report the unavailable source and stop. Do not invent a trade, holding, amount, ticker, or filing.

For the production source allowlist and ingestion rules, read [references/data-sources.md](references/data-sources.md). For the remote request and response contract, read [references/data-api.md](references/data-api.md). For field meanings and disclosure limits, read [references/data-model.md](references/data-model.md) when explaining or aggregating records. Read [references/frontend-data-map.md](references/frontend-data-map.md) before changing a Dashboard metric or field so the backend projection and UI stay aligned.

## Production source boundary

- Congress: ingest only U.S. House Clerk and Secretary of the Senate eFD official filings. House and Senate ethics committee pages supply rules and deadlines only.
- Executive branch: ingest only official OGE/agency public 278-T and 278e records. If Form 201 or another manual request is required, return `manual_request_pending`; do not submit it automatically.
- Market prices: use only Alpaca SIP completed-session daily bars as the separate background-price dataset.
- Never ingest SEC EDGAR 13F, GuruTrack, Quiver, Capitol Trades, another aggregator, a paid/private holdings feed, social media, news, search snippets, or scraped quote pages.
- A production transaction or holding can enter the canonical arrays only as `official_matched`, with a stable person ID, allowed `source_id`, and official HTTPS evidence URL.

## Display rules

- Colour a price-change figure green when it is positive and red when it is negative, following the US market convention requested for this board — not the red-up/green-down convention used in mainland Chinese markets — and leave the figure uncoloured when no comparable price exists rather than rendering a missing value as a decline.
- Render every trade date and filing date from the literal calendar date in the record: `transaction_date` is a bare date and `filed_at` carries the filing authority's UTC offset, so converting either through the viewer's local timezone can display a date one day off.
- The global source module shows only the newest official disclosure-source link per source and does not duplicate reported-holdings detail. Every displayed person identity links to the full-screen profile, and every displayed ticker links to the full-screen security view.

## Non-negotiable disclosure rules

- Say “disclosed purchase”, “disclosed sale”, or “reported holding”; even with the latest verified holdings filing, describe it as a dated reported holding rather than a current real-time position.
- Keep `transaction_date`, `filed_at`, and `data_cutoff_at` distinct.
- Amounts are reported ranges. Display `$1,001–$15,000`, not an estimated exact trade size. Aggregate lows and highs separately. A per-direction total is that direction's ranges added up — never present it as a net inflow, net outflow, or net position change.
- A ranked display such as “largest disclosed purchase” is a descriptive statistic about filings in a window. It is not a recommendation, rating, score, signal, or forecast, and it must not be phrased as one.
- Preserve the disclosed owner: self, spouse, dependent child, joint, or unknown. Do not attribute a spouse transaction directly to the official.
- A periodic transaction report is not a complete portfolio. Holdings require the applicable annual or termination filing.
- Treat “newly reported”, “range increased”, “range decreased”, and “no longer reported” as comparisons between two filing snapshots, not proof of an exact purchase, sale, or complete exit. Use PTR/278-T records for transaction claims.
- Preserve amendments and supersession links. Prefer the latest official amendment while noting that it changed an earlier filing.
- Keep `official_raw_unparsed`, `manual_request_pending`, and `superseded` records in coverage/audit output; only `official_matched` rows enter production financial arrays and aggregates.
